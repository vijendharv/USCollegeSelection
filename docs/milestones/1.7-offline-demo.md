# Milestone 1.7 — Local end-to-end demo

**Status:** Complete

**Completed:** 2026-07-01

**Pull request:** Pending

## Objective

Run the complete Stage 1 workflow on a local computer using the full real College Scorecard DuckDB database: load a confirmed student JSON profile, select and classify schools, build gap analysis, and generate matching JSON, PDF, and Excel files. No cloud hosting or paid service is required.

## Delivered

### Real local demo command

The new command is:

```bash
uv run python -m app demo
```

By default it reads:

- `examples/demo-student-profile.json`, a synthetic but realistic student;
- `data/college.duckdb`, created from the full official dataset by `refresh-data`; and
- `demo-output/`, the ignored root for private generated sessions.

The demo command never invokes the networking layer. If the real database does not exist or is unhealthy, it stops with an instruction to run `uv run python -m app refresh-data`. The refresh is the one explicit network step; subsequent demos are entirely local.

### Nationwide selection and balanced output

The demo pages through every eligible institution in local DuckDB. It applies the student's preferred states while always retaining schools explicitly entered by the user. Every matching school is classified before the final list is balanced to at most ten schools in each category. The cap is configurable from one through ten with `--schools-per-category`.

The result summary reports:

- whether a database had to be built in explicit fixture-test mode;
- total local database institutions scanned;
- institutions matching the profile's geography;
- schools included in the report;
- category counts;
- output directory; and
- generated file paths.

### Consistent local outputs

Each run creates a random private session directory containing:

- `college-report.json` — the canonical classified list and gap analysis;
- `college-report.pdf` — the printable report; and
- `college-report.xlsx` — the five-sheet workbook.

All three originate from the same `CollegeReport`; exporters do not recalculate results.

### Manual-profile input

The `--profile` option accepts any JSON document that validates as `StudentProfile`. The command runs the existing completeness assessment and reports blocking missing inputs instead of inventing values. The included example covers a senior-year applicant, weighted/unweighted-safe GPA data, optional SAT, AP coursework, budget, majors, preferred states, and a user-entered school.

### Explicit fixture test mode

Automated tests cannot download a nationwide dataset. Passing `--fixture` explicitly builds a small DuckDB database from the frozen public Scorecard CSV. This mode validates the exact same ingestion, classification, reporting, storage, PDF, and Excel path, but it is clearly documented as an engineering test rather than the real user demo.

## Design decisions

- Make the full real local database the default; never silently substitute fixture data.
- Require only one intentional network refresh, then keep analysis and exports offline.
- Scan all local institutions before balancing categories rather than selecting the first database rows.
- Apply geography as the currently supported matching input and retain every user-entered school.
- Cap each category at ten to keep PDF and Excel outputs useful.
- Keep the frozen fixture behind an explicit flag for deterministic automated tests.
- Store each run in a random private session directory.

## How to test locally

Install and verify:

```bash
uv sync --all-groups
uv run pytest
```

Download and build the real local database once:

```bash
uv run python -m app refresh-data
```

Run the real local demo:

```bash
uv run python -m app demo
```

Open the output directory printed by the command and inspect all three files. Run it again without internet access to confirm the existing DuckDB database is reused.

Use a manually edited profile:

```bash
cp examples/demo-student-profile.json my-student-profile.json
uv run python -m app demo --profile my-student-profile.json --schools-per-category 5
```

Run the small fixture path without a full data download:

```bash
uv run python -m app demo \
  --fixture tests/fixtures/scorecard/institutions.csv \
  --database /tmp/uscs-demo/college.duckdb \
  --output-dir /tmp/uscs-demo/output
```

## Verification

Automated coverage verifies:

- strict example-profile validation and readiness;
- explicit fixture ingestion into DuckDB;
- database reuse on a second run;
- a helpful failure when the real database has not been refreshed;
- geographic matching and user-entered school retention;
- JSON, PDF, and five-sheet Excel generation;
- consistent school counts across outputs; and
- a successful CLI run without networking.

The complete suite contains 78 passing tests. All Ruff lint, Ruff format, strict mypy, and diff checks passed.
