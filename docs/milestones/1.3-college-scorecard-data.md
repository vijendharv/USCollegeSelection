# Milestone 1.3 — College Scorecard data

**Status:** Complete

**Completed:** 2026-07-01

**Pull request:** [#7 Implement College Scorecard data store](https://github.com/vijendharv/USCollegeSelection/pull/7)

## Objective

Load current, real US college data into a local DuckDB database through the networking and storage boundaries. Provide safe refreshes, auditable source metadata, institution lookup, and basic filters without querying a remote API during user searches.

## Delivered

### Official source discovery

`ScorecardDataSource` starts from the official College Scorecard data page rather than hard-coding a dated archive URL. It parses the page for the single **Most Recent Institution-Level Data** ZIP and resolves its current download URL.

The validated source at implementation time was:

- Data page: `https://collegescorecard.ed.gov/data/`
- Archive: `Most-Recent-Cohorts-Institution_06102026.zip`
- Official update date: 2026-06-10
- Compressed size: approximately 23 MB
- Institution CSV size: approximately 100 MB

The networking layer streams the ZIP to `data/raw/` and records the final URL, retrieval time, ETag when available, and byte count.

### Real-data refresh command

The application now exposes:

```bash
uv run python -m app refresh-data
```

By default, the command:

1. discovers the current official archive;
2. downloads it to `data/raw/`;
3. extracts its institution CSV in a temporary storage directory;
4. builds a temporary DuckDB database;
5. validates schema, identity, ranges, costs, duplicates, and row counts; and
6. atomically replaces `data/college.duckdb` only after every check passes.

The minimum expected eligible-institution count is configurable through `--minimum-institutions` and defaults to 1,000. This is a safety threshold, not a result limit.

### DuckDB schema

The initial schema intentionally contains two tables:

- `institutions` — normalized fields required by discovery and the next classification milestone.
- `dataset_versions` — provenance and reproducibility metadata for the active import.

The institution table includes:

- IPEDS UNITID and identity;
- city, state, postal code, coordinates, and URLs;
- public/private ownership and main-campus status;
- predominant and highest degree;
- online-only status and undergraduate enrollment;
- admission rate;
- SAT and ACT ranges;
- in-state and out-of-state tuition;
- cost of attendance and average net price;
- graduation and retention rates; and
- median earnings ten years after entry.

Institutions are eligible when College Scorecard marks them currently operating, their highest degree is bachelor's or graduate level, and they report positive undergraduate enrollment. This includes institutions that award bachelor's degrees even if a lower degree is predominant, while excluding graduate-only institutions.

### Null and sentinel handling

Federal values such as `NA`, `NULL`, `PrivacySuppressed`, malformed numerics, and unavailable fields become null rather than fabricated zeros.

The live archive exposed a real negative average-net-price sentinel for Colegio Universitario de San Juan. Cost, enrollment, and earnings values are now accepted only when nonnegative; negative values become null. The frozen fixture retains this real row to prevent regression.

### Atomic publication

Refreshes never modify the working database in place. The storage layer:

- builds a uniquely named temporary DuckDB file beside the target;
- validates it before publication;
- closes all writers; and
- publishes with an atomic filesystem replacement.

If ZIP extraction, required columns, data validation, or database creation fails, the temporary file is removed and the existing database remains usable.

### Dataset provenance

Every successful refresh stores:

- version ID;
- source name and final URL;
- archive member name;
- release date;
- retrieval timestamp;
- SHA-256 checksum;
- raw and eligible row counts; and
- local schema version.

The version ID is derived from the archive checksum, so identical source bytes produce the same version identity.

### Typed query interface

`DuckDBCollegeStore` supports:

- health checking;
- lookup by IPEDS UNITID;
- current dataset-version lookup; and
- filtered, ordered, paginated institution searches.

Initial filters include name, state, ownership, maximum tuition, minimum acceptance rate, limit, and offset. Queries use parameters rather than interpolating user values.

### Frozen public-data fixture

Offline tests use a reduced-column extract of eight real public Scorecard rows. It includes:

- public and private institutions;
- several states and Puerto Rico;
- selective and broadly admitting institutions;
- missing test and cost values;
- a degree-below-bachelor's exclusion case; and
- a graduate-only institution with no undergraduate enrollment; and
- the real negative-net-price sentinel.

The fixture is public data, not synthetic student or college information, and records its exact source and date.

## Design decisions

- Prefer one official bulk download over thousands of runtime API calls.
- Discover the dated archive from the official page so refreshes survive filename changes.
- Keep the raw archive locally for auditability and repeatable rebuilding.
- Store only fields currently used rather than copying roughly 2,400 source columns into the application schema.
- Use UNITID as the institution primary key.
- Use one initial institution table rather than prematurely splitting every metric into separate tables.
- Treat suppression, missing values, and invalid sentinels as null.
- Build and validate a new database before replacing the current one.
- Keep DuckDB and SQL inside the storage layer.
- Use real public rows for offline tests while keeping the fixture small.

## How to use it

Refresh the real dataset:

```bash
uv run python -m app refresh-data
```

The default local files are:

```text
data/raw/Most-Recent-Cohorts-Institution_<release>.zip
data/college.duckdb
```

Both locations can be moved through the `USCS_DATA_DIR` environment variable:

```bash
USCS_DATA_DIR=/tmp/uscs-data uv run python -m app refresh-data
```

Query the generated database:

```python
from pathlib import Path

from app.models import InstitutionFilters, Ownership
from app.storage import DuckDBCollegeStore

with DuckDBCollegeStore(Path("data/college.duckdb")) as store:
    school = store.get_institution(166027)
    public_california = store.search_institutions(
        InstitutionFilters(states=["CA"], ownership=[Ownership.PUBLIC])
    )
```
