# Milestone 1.8 — Fit-ranked shortlist and holistic alignment

**Status:** Planned

**Completed:** Not yet complete

**Pull request:** Not yet implemented

## Objective

Select the strongest-fitting college-and-major combinations within each admissions category instead of taking the first alphabetically loaded records. Keep the deterministic Safety / Likely, Target, Reach, and Insufficient Data classification separate from a transparent major-specific fit rank, and use confirmed résumé evidence only as holistic alignment context.

## Problem being corrected

Milestone 1.7 classifies every matching institution, but the database returns institutions ordered by name and the balancing step takes the first ten results in each category. The resulting shortlist is therefore alphabetically biased rather than ranked by quality or student fit.

The current profile also stores résumé information as prose in academic notes. The classifier counts advanced courses, GPA, tests, and institutional selectivity; résumé evidence does not participate in school matching or ordering. This is appropriately conservative for admissions classification, but incomplete for recommendations.

## Requirements

### 1. Preserve classification boundaries

- Do not modify a school's admissions category based on résumé content, activities, awards, intended major, cost, geography, outcomes, or an external ranking.
- Keep classification methodology and fit-ranking methodology separately versioned.
- Display the category and fit rank as distinct concepts in every output.
- Continue to label classifications as planning estimates, not admission probabilities or guarantees.

### 2. Create a deterministic fit score

- Treat `student × institution × intended major` as the ranking unit and compute a separate fit score for every requested major the institution offers.
- Compute major-specific scores after all matching schools have been classified.
- Rank college-major combinations only against combinations for the same intended major and admissions category.
- Use stable UNITID as the final tie-breaker; alphabetical order must never be a scoring input.
- Produce a separate Safety / Likely, Target, Reach, and Insufficient Data list for each intended major.
- Select the highest-ranked college-major combinations up to the requested category cap for each major and category.
- Produce a consolidated view that favors schools fitting several intended majors, without replacing or averaging away the separate major lists.
- Always retain explicitly entered schools and label whether they were selected by rank or retained by the user.
- Store the overall score, each component score, missing inputs, methodology version, and explanation in the canonical report.

The admissions category remains institution-level unless a reliable, sourced major-specific admission rate is available. A major-specific fit rank must not imply that a university-wide acceptance rate represents admission odds for direct-entry or capacity-constrained programs such as engineering, nursing, or certain sciences. The report must flag that limitation for affected programs when the data is unavailable.

The first methodology should use these transparent components. Exact weights must be constants in code, sum to 100, and be recorded in the report:

| Component | Evidence | Required behavior |
|---|---|---|
| Academic fit | Compatible GPA/test position, acceptance rate, classification confidence | Measure relative academic fit without changing the category |
| Major fit | Intended majors mapped to offered CIP programs | Reward confirmed program availability and breadth; never infer major selectivity |
| Student preferences | Preferred/excluded states and a comparable stated budget | Use only preferences the student supplied; a missing budget is neutral and visible |
| Outcomes | Graduation, retention, and earnings fields from College Scorecard | Normalize transparently; describe these as outcomes, not universal college quality |
| Holistic alignment | Confirmed résumé themes matched to offered program families | Reward explainable alignment only; do not assign an admissions advantage |

Data completeness must be reported as confidence alongside the score. Missing optional evidence must not silently become a zero. The methodology must define either weight redistribution among available components or a neutral missing-data treatment and test it explicitly.

### 3. Add real major/program data

- Extend the networking and storage pipeline to ingest the latest free College Scorecard field-of-study data needed for institutional CIP offerings.
- Store UNITID, CIP code, credential level, program title when available, source version, and provenance.
- Map the student's intended-major text to a reviewed set of CIP codes or families.
- Preserve ambiguous mappings and show them for confirmation instead of silently choosing one.
- Treat program presence as availability, not proof of program quality, direct admission, capacity, or competitiveness.
- Use available program-level completion and outcome fields as explicitly named strength indicators, subject to suppression and data-quality rules; do not collapse them into an unsupported claim of program prestige.
- Permit the same institution to rank differently for Biology, Chemistry, Neuroscience, Biomedical Engineering, or any other intended major.

### 4. Structure confirmed résumé context

- Add a first-class profile representation for confirmed activities and derived themes; do not parse free-form academic notes during ranking.
- Preserve original confirmed facts such as role, organization, duration, hours, awards, and descriptions.
- Derive reviewable themes such as healthcare, research, service, leadership, competition, employment, arts, or athletics.
- Match themes only to school evidence that is actually available. In this milestone, CIP/program-family alignment is sufficient; claims about research labs, hospitals, clubs, or special programs require a sourced school dataset and are deferred.
- A profile without a résumé must still rank successfully, with holistic alignment marked unavailable and its weight handled by the documented missing-data rule.

### 5. Define “best” honestly

- Call the result an internal **fit rank**, not a national college ranking.
- Do not scrape or reproduce proprietary ranking lists.
- Expose why a school ranked highly: for example, academic fit, relevant programs, strong completion outcomes, affordability, or location preference.
- Let users distinguish hard filters from ranking preferences in a later UI; for this local milestone, existing profile preferences remain the inputs.
- Avoid a single unexplained prestige score. Selectivity may inform academic fit but must not become a proxy for universal quality.

### 6. Update all outputs

- JSON must group exact fit-score inputs and methodology metadata by intended major, with a separate consolidated view.
- Excel must include one normalized, filterable major-ranking table with major, category rank, overall fit score, component scores, fit confidence, and concise rationale. Separate worksheets per major are not required.
- PDF must contain a clearly labeled section for each intended major, present schools in fit-rank order within each category, and include a concise consolidated multi-major summary.
- Missing major, outcome, cost, and holistic evidence must remain visible.
- The CLI summary should state that results are fit-ranked and identify the fit methodology version.

## Proposed implementation slices

1. **1.8a — Ranking model and unbiased selection:** add fit models, deterministic scoring for currently stored fields, replace alphabetical truncation, and add regression tests.
2. **1.8b — Major data and CIP mapping:** ingest Scorecard field-of-study data and add reviewed intended-major mappings.
3. **1.8c — Structured holistic context:** model confirmed résumé activities/themes and connect explainable theme-to-program alignment.
4. **1.8d — Report and export presentation:** add rankings and explanations consistently to JSON, PDF, Excel, and local documentation.

Each slice should be independently reviewable. If a slice changes a public report schema, update the report version and migration notes in the same pull request.

## Acceptance criteria

- Reversing or randomizing candidate input order produces identical ranked results.
- A higher-ranked school is selected over an alphabetically earlier lower-scoring school in the same category.
- Exactly the highest-scoring requested number of college-major combinations is returned per major and category, plus any retained user-entered schools.
- The same institution can receive different ranks for different intended majors based on real program evidence.
- Every intended major receives its own categorized list and appears in the consolidated multi-major view when evidence supports it.
- Institution-level categories and major-specific fit ranks are labeled separately, including a warning when major-specific selectivity is unavailable.
- A résumé-rich and résumé-empty version of the same academic profile receive identical admissions categories.
- Confirmed résumé themes can change holistic-alignment ordering only when supported by school program evidence.
- Intended-major matching uses stored CIP evidence and exposes ambiguous or missing mappings.
- Missing budget, résumé, program, or outcomes data is visible and follows the documented neutral/redistribution rule.
- Every score can be reconstructed from the report's component values, weights, and methodology version.
- PDF, Excel, and JSON contain the same schools, category order, fit ranks, scores, and explanations.
- The full automated suite, Ruff, formatting, and strict mypy checks pass.

## Verification plan

- Unit-test score boundaries, normalization, missing-data handling, stable tie-breaking, and methodology metadata.
- Property-test or parametrically test input-order independence.
- Use synthetic colleges designed so alphabetic order conflicts with fit order.
- Test major mappings for exact, synonymous, broad, ambiguous, and unknown inputs.
- Test that one institution ranks differently for two majors when their program evidence differs.
- Test separate per-major caps and deterministic consolidated-list behavior.
- Test that résumé context never changes classification.
- Test user-entered school retention outside caps and filters.
- Test an offline end-to-end run using a frozen public institution/program fixture.
- Compare ranking fields across canonical JSON, parsed PDF text, and Excel cells.
- Run a real local smoke test against the full refreshed DuckDB database and inspect Saanvi's category ordering manually.

## Design decisions

- Separate admission likelihood from recommendation fit to avoid false precision.
- Prefer reproducible public-data signals over proprietary rankings or opaque model judgment.
- Use outcomes as named components rather than claiming an objective definition of the “best” college.
- Require structured, confirmed résumé context; unstructured notes are not safe ranking inputs.
- Limit initial résumé alignment to evidence supported by the free program dataset.
- Keep networking limited to the explicit data-refresh workflow; ranking remains local and offline.

## Deferred

- Institution-specific evaluation of extracurricular strength or admission probability.
- Claims about labs, hospitals, research access, clubs, honors programs, or experiential opportunities until sourced official-school data exists.
- Major-specific acceptance rates, which are rarely published consistently.
- Proprietary or licensed national rankings.
- Personalized financial-aid estimates beyond clearly labeled public price fields.
- User-adjustable scoring weights and interactive ranking controls.
